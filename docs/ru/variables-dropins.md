# Переменные и Drop-in

Gixy содержит встроенные модели переменных, включая точное имя `$brotli_ratio`.
Модель `[0-9.]*` описывает десятичное значение или отсутствие значения: исключает
CR/LF и `/`, но сохраняет точки для консервативной проверки SSRF. Источник:
[getter ngx_brotli v0.1.4](https://github.com/GetPageSpeed/ngx_brotli/blob/v0.1.4/filter/ngx_http_brotli_filter_module.c#L778-L816).
Это описание возможных значений, а не проверка установки или загрузки модуля.
Общего безопасного префикса `brotli_` нет; неизвестные переменные по-прежнему
вызывают диагностические сообщения.

## Слои и приоритет

Обычный CLI, включая запуск без аргументов и stdin, использует слои по возрастанию
приоритета:

1. Встроенные модели.
2. Файлы поставщиков в `/usr/share/gixy/vars.d`.
3. Файлы администратора в `/etc/gixy/vars.d`.
4. Явные каталоги `--vars-dirs` в указанном порядке (последний выше).

Каждый каталог представляет отдельный слой. Файлы `.cfg` и `.conf` читаются по
имени; последнее корректное определение ключа побеждает, в том числе внутри
одного файла. Ошибочная строка не удаляет предыдущее корректное определение:
предупреждение содержит путь и номер строки.

Сначала выбирается самый высокий слой с подходящим определением, затем точное
имя, затем самый длинный подходящий префикс с окончанием `_`. Поэтому `http_`
верхнего слоя перекрывает `http_host` нижнего. В одном слое точное имя выше
префикса, а `http_special_` выше `http_` для `$http_special_value`. Это исправляет
прежнюю зависимость выбора префикса от порядка вставки. Переменные, заданные в
анализируемой конфигурации NGINX, сохраняют приоритет над каталогом моделей.

## Управление и изоляция

```sh
gixy --vars-dirs /etc/gixy/vars,~/.config/gixy/vars
```

```cfg
# Скалярное значение, без квадратных скобок
vars-dirs = /etc/gixy/vars, ~/.config/gixy/vars
load-default-vars = false
```

`--no-default-vars` отключает системные каталоги, сохраняя встроенные модели и
явно выбранные каталоги. `--load-default-vars` включает системные каталоги.
Противоположные флаги вместе запрещены. Канонический ключ: `load-default-vars`;
переменная окружения: `GIXY_LOAD_DEFAULT_VARS=true` или `false`. Приоритет:
CLI > окружение > конфигурация > значение режима. Явное `false` сохраняется,
включая `--write-config`. Явные каталоги всегда выше включённых системных слоёв.
Старые `/etc/gixy/vars` и `~/.config/gixy/vars` работают при явном выборе.

Библиотека `Config(load_default_vars=False)` и `--server` по умолчанию используют
только встроенные модели. Оператор может включить системную политику или задать
`vars_dirs` при запуске. Отдельные запросы сервера и загруженный текст NGINX не
могут изменить политику или выбрать пути. Для каждой проверки создаётся новый
каталог, общий для её дочерних контекстов: модели между проверками не перетекают.
Это не обещание общей потокобезопасности анализатора.

## Формат и доверие

Строка: `name value`, `name = value` или `name: value`. Имя состоит из ASCII-букв,
цифр и `_`, начинается с буквы или `_`, не содержит `$`; окончание `_` задаёт
префикс. Числовые regex-группы не входят в каталог.

```cfg
foo_host "example.com"
foo_literal 'a.b[$http_host]'
foo_uri r'/[^\s]*',
legacy_uri /[^\s]*
operator_asserted_safe none
```

Обычные кавычки задают литерал без подстановки переменных, Python-декодирования
или выполнения. `r'...'` и `r"..."` задают regex; старые regex без кавычек также
поддерживаются. Синтаксис regex проверяется статически, без поиска по строкам.
Допустима завершающая запятая. `none`, `null` (без учёта регистра), `''` и `""`
явно утверждают отсутствие пользовательского управления. Это доверенная
политика, способная подавлять находки: применяйте только с обоснованием.
Пропущенное значение, незакрытые кавычки, неверное имя и некорректный regex
отклоняются с предупреждением. Пустые строки и комментарии `#`/`;` игнорируются.

Автоматические файлы должны быть обычными файлами root, без записи для группы
и остальных; те же требования действуют на каталог и всех предков. Символические
ссылки, включая предков, отклоняются. Используются удерживаемые дескрипторы с
no-follow; если платформа этого не поддерживает, системная политика пропускается
с предупреждением. Отсутствующие необязательные каталоги допустимы; сканирование
не создаёт каталогов.

Явные пути являются выбором доверенного оператора, поддерживают `~` и доступны
не-root пользователям. Ошибки чтения и отсутствующие явные пути предупреждаются.
Неявного поиска в текущем или домашнем каталоге нет. RPM модуля может поставлять
обычный vendor-файл root:root/0644 без зависимости от Gixy. Общие vendor-каталоги
имеют root:root/0755; локальные переопределения находятся в `/etc/gixy/vars.d`.
После удаления файла модуля остаётся встроенная модель. Политика меняет только
анализ, а не поведение NGINX.
